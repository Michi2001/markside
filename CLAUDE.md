# CLAUDE.md

VS Code extension "Markdown Live Editor": Obsidian/Typora-style live editing of `.md` files in a custom editor (Milkdown Crepe inside a webview), with image paste and hand-off of the selection to Claude Code. PDFs open in a second custom editor with always-visible Markdown notes in the margin.

## Commands

```bash
npm install
npm run build        # esbuild: dist/extension.js + dist/webview.js/.css
npm run watch        # rebuild on change
npx tsc --noEmit     # typecheck (esbuild does not check types)
npm run package      # build .vsix (vsce)
```

**After every change:** package and install the extension right away, so the user's normal VS Code runs the new version (then remind them to run "Developer: Reload Window"):

```bash
npm run package && code --install-extension markdown-live-editor-0.1.0.vsix --force
```

`F5` (`.vscode/launch.json`) builds and launches an Extension Development Host with the `notes/` folder as test workspace. There are no automated tests; verify changes manually in that instance.

## Architecture

Three bundles (see `esbuild.mjs`):

- **Extension host** (`src/extension.ts`, `src/liveEditor.ts`, `src/pdfEditor.ts`, `src/sidecar.ts`, `src/assets.ts`, `src/preserve.ts`, `src/drawingServer.ts`): Node/CJS, `vscode` is external.
  - `extension.ts`: registers the custom editor `mdLive.editor` and the commands `mdLive.open`, `mdLive.openAsText` (swap the active tab via `vscode.openWith`), `mdLive.sendSelectionToClaude` `mdLive.insertDrawing`, `mdLive.showIpadUrl`, `mdLive.renewIpadUrl` (new token, old URLs stop working), `mdLive.chooseTheme` (writes the `mdLive.theme` setting), `mdLive.chooseFontSize` (font size of the active note or PDF only, stored per file URI in `globalState` by `FontSizes` (`src/fontSizes.ts`, moved along in `onWillRenameFiles`); notes without one use the setting `mdLive.fontSize`; drives `--crepe-base-font-size` via `--mdlive-font-size` on `body`) and `mdLive.chooseDrawingDevice` (writes `mdLive.drawingDevice`; the editor title shows one variant per device, `mdLive.chooseDrawingDevice.<device>`, picked via `config.mdLive.drawingDevice` so its icon matches; also a status bar item shown while a live editor tab is active, `registerDeviceStatus`).
  - `liveEditor.ts`: `LiveEditorProvider` (`CustomTextEditorProvider`). The `TextDocument` is the single source of truth; the webview is only a view.
  - `assets.ts`: per-note image folders (saving, cleanup, sync on rename/copy/delete) and the collapsed headings file.
  - `pdfEditor.ts`: `PdfEditorProvider` (`CustomReadonlyEditorProvider`, `mdLive.pdf`, default for `*.pdf`; `supportsMultipleEditorsPerDocument`, so one PDF can be open in several panels, each with its own `ownText`/`echo`/undo stacks, synced via the notes TextDocument), see PDF notes.
  - `sidecar.ts`: format of the PDF notes file (parse, add, set body, delete) and of Claude's explanations (`parseExplanations`); no vscode imports, also used by the PDF webview.
  - `preserve.ts`: keeps the original source of unchanged blocks when the webview sends an edit.
  - `drawingServer.ts`: local HTTP server for drawing on an iPad (see Handwriting).
  - `explain.ts`: `mdLive.explainSlides` (see Explanations by Claude).
- **PDF webview** (`src/webview/pdf/`): fourth bundle `dist/pdf.js`/`.css` (pdf.js + note cards). `esbuild.mjs` copies pdf.js' worker (`dist/pdf.worker.min.mjs`) and `cmaps`/`standard_fonts`/`wasm` (`dist/pdfjs/`).
- **iPad page** (`src/ipad/`): third bundle `dist/ipad.js`/`.css`, reuses `openDrawingEditor` from `src/webview/drawing.ts`.
- **Webview** (`src/webview/`): browser/IIFE, bundles Milkdown Crepe including KaTeX fonts into `dist/assets/`.
  - `main.ts`: the note's editor, inline title, `Alt+Y` folding, message handling.
  - `noteEditor.ts`: `createNoteEditor` (Crepe with all plugins, image paste/drop, drawing), shared by both webviews; `installShortcuts` (global `keydown` formatting shortcuts acting on the last focused editor, `getActiveEditor`/`setActiveEditor`). `host.ts`: `acquireVsCodeApi` wrapper, image upload/remote drawing requests, `init` settings and the messages common to both webviews (`handleHostMessage`).
  - `imageView.ts`: resizable image blocks. `moveBlocks.ts`: `Alt+Up/Down` and `Tab` in lists. `headings.ts`: heading level shortcuts. `fold.ts`: collapsible heading sections. `highlight.ts`: `==highlight==` mark. `drawing.ts`: handwriting canvas. `style.css`: maps Crepe theme variables to VS Code theme variables.

### Message protocol webview ↔ extension

| Direction | Type | Purpose |
|---|---|---|
| Webview → Ext | `ready` | Webview loaded, requests `init` |
| Ext → Webview | `init` | Document text + `baseUri` (note's folder) + `theme` + `fontSize` + `title` + `folds` |
| Webview → Ext | `rename` / Ext → Webview `title` | Inline title edited → rename the note; `title` restores the old title if nothing was renamed |
| Ext → Webview | `fontSize` | The note's font size changed (`FontSizes` or default setting) → `--mdlive-font-size` on `body` |
| Ext → Webview (PDF view) | `notesWidth` | `mdLive.pdfNotesWidth` changed |
| Ext → Webview | `theme` | Color mode changed (`mdLive.theme`: `auto`/`light`/`dark`) → `body[data-theme]` |
| Webview → Ext | `edit` | Full Markdown after a change |
| Webview → Ext | `folds` | Collapsed headings changed → `foo.assets/.folds.json` |
| Ext → Webview | `update` | External change to the document (`replaceAll`) |
| Webview → Ext | `saveImage` / Ext → Webview `imageSaved` | Save image (base64), return relative path |
| Ext → Webview | `requestSelection` / Webview → Ext `selection` | Selected plain text for Claude |
| Ext → Webview | `insertDrawing` | Open the drawing surface for a new handwriting block |
| Ext → Webview | `drawingDevice` | `mdLive.drawingDevice` changed (`mac`/`ipad`/`ipadUsb`/`sidecar`; also sent in `init`) |
| Webview → Ext | `drawRemote` / Ext → Webview `drawingSaved` | Draw on the drawing page (iPad or Sidecar browser window; `drawing`: strokes + optional background image, `src`: edited image or `null`), return the saved path or `null` |

Types for messages to the extension live in `WebviewMessage` (`liveEditor.ts`, `pdfEditor.ts`); when adding messages, update both sides.

PDF view (`pdfEditor.ts` ↔ `webview/pdf/main.ts`): `ready` → `init` (`pdfUrl`, `distUri`, `baseUri`, theme/fontSize/drawingDevice, `sections`); Ext → Webview `notes` (all sections after a change not made by the webview itself); Webview → Ext `editNote` (`key`, body Markdown), `addNote` (`anchor`, `label`, `body`, `replace`: keys deleted in the same edit), `deleteNote` (`key`, `discard`), `undo` (`redo`), `askClaude` (`page`, `quote`?, `rects`?, `key`?, `note`?, `explanation`?), `view` (`page` in view, `pages` count; on load and scroll), `pageTexts` (answer to Ext → Webview `requestPageTexts`), `deleteExplanation` (`page`); Ext → Webview `explanations` (sections of `paper.pdf.claude.md`, also in `init` with `showExplanations`/`expandExplanations`), `showExplanations` (`show`, `expand`); plus `saveImage`, `drawRemote`, `selection` and the settings messages as above.

### Key details

- **Echo prevention:** `webviewText` (extension) and `lastSynced` (webview) prevent own changes from being mirrored back. Keep this in mind when changing the sync logic.
- **Minimal edits:** `applyMinimalEdit` replaces only the changed middle part so VS Code's undo and dirty state stay sensible. Edits run serially via `editQueue`, chained per document URI through `queueEdit` (shared by live editors, all PDF panels of the same notes and `saveToNote`: an edit applied while another one is in flight would get a stale range and garble the text); `applyAdopted` relinks foreign images only if the document didn't change meanwhile. CRLF documents are converted on `edit`.
- **Markdown normalization:** Crepe serializes the whole Markdown itself on every change (bullets set to `-` via `remarkStringifyOptionsCtx`, tables padded, …). To keep the raw Markdown untouched outside the edited blocks, the `edit` handler runs `preserveSource` (`preserve.ts`) first: plain remark (gfm + math) splits the document text and the webview's Markdown into top-level blocks, compares them by their remark-normalized form (LCS) and keeps the original source (and the gaps between adjacent original blocks) for every matched block. Only changed top-level blocks get Crepe's formatting (a whole list or table when one item/cell changes). The webview keeps its own serialization; `webviewText` holds the preserved text, so no `update` echoes back.
- **Images:** each note `foo.md` owns a sibling folder `foo.assets/`; images are saved there as `<timestamp>.<ext>` and linked relatively (`foo.assets/123.png`, note name URI-encoded). Relative image paths are resolved in the webview via `baseUri`; `localResourceRoots` and the CSP in `getHtml` must allow this. `assets.ts` keeps a single owner per folder: when the last panel of a note closes, `cleanupAssets` moves files not referenced in the note (disk + unsaved text) to the trash; `adoptAssets` copies images linked from another note's folder (pasted image, copied note) into the own folder and relinks them (on every `edit`; on `onDidCreateFiles` it also searches the workspace via `findFiles`, so notes copied into another folder get their images); `registerAssetSync` moves/renames the folder with the note (`onDidRenameFiles`, relinks on rename) and trashes it when the note is deleted. Only operations inside VS Code are tracked; in Finder note and folder must be moved together. Known limitation (documented in README): `findFiles` only searches the current workspace, so a note copied from another workspace/window gets broken image links. The user hides the folders via `files.exclude` `"**/*.assets": { "when": "$(basename).md" }`, and a PDF's notes/explanations via `"**/*.pdf.md": { "when": "$(basename)" }` and `"**/*.pdf.claude.md": true`.
- **Resizable images:** `imageView.ts` extends Crepe's `image-block` schema (`extendImageBlockSchema`, adds `width` and a real `alt`; Crepe's `ratio`-in-alt is ignored) and replaces its node view after `crepe.create()` via `view.setProps` (`createImageBlockView`; empty image blocks keep Crepe's upload placeholder). Corner handles set `width` in px. Unresized images serialize as `![alt](src)`, resized ones as `<img src="…" width="N">`; `remarkHtmlImages` parses standalone `<img>` tags with a numeric width back into image blocks.
- **Handwriting:** `src/webview/drawing.ts` opens a full-window overlay (`openDrawingEditor`) with an infinite canvas: the canvas only covers the visible area and is redrawn with a view offset and zoom (`viewX`/`viewY`/`zoom`; wheel scrolls and Ctrl+wheel/trackpad pinch zooms on the Mac, one finger pans and two fingers pinch-zoom while the pen is up; zoom only affects the view), the grid is drawn on it; strokes are drawn as round-capped polylines split into runs of equal width (`runs`; pen width follows pressure, `pen: false` = constant width for mouse/pressureless input; `highlighter: true` = constant width, semi-transparent, painted below the ink via `paintOrder`). The same runs are used while writing, after pen-up and in the SVG (`<polyline>`s), so a stroke never changes when the pen lifts (an earlier outline library caused wobble and frayed edges). Tools (`Tool`): pen, highlighter (tray slots with changeable colors, stored in `localStorage`; tapping the selected one again opens a palette popover whose rainbow swatch wraps a hidden `<input type=color>`; `sizes` holds one size for all pens/shapes and one for all highlighters, set via the five toolbar size steps (`SIZES`)), eraser (`eraserMode`: stroke removes touched strokes, point cuts them via `eraseFrom`; hit test against segments), lasso (select by loop, drag inside the box to move) space (moves all strokes below the pen-down line vertically) and shape (`SHAPES`, picked in a popup menu; `shapePoints` turns the dragged box into one polyline stroke, arrow heads/axes retrace their path, so shapes are ordinary strokes); each pen-down starts a `Gesture` of the current tool, the move preview uses `selection` + `offset`; undo/redo stacks hold whole stroke arrays. Saved via `saveImage` as `<timestamp>.drawing.svg` (cropped to the strokes' bounding box; the stored points are moved accordingly) with the stroke JSON in `<metadata id="mdlive-drawing">`; `isDrawing` checks the suffix. Opened via `Alt+D`, the slash menu item (`buildMenu` in `main.ts`) or `mdLive.insertDrawing`; double-click on a drawing in `imageView.ts` reloads the strokes (`fetch`, hence `connect-src` in the CSP) and every save writes a new file and swaps `src` (keeps undo working; old files go via `cleanupAssets`). Ink is stored dark; `.mdlive-ink` inverts it in dark themes. The overlay is styled Fluent-like with its own amber accent (`--mdlive-accent*` in `drawing.css`, lighter in dark themes). Drawing on an image: double-click on a local non-drawing image calls `editDrawing` with its displayed width; `imageDrawing` fetches it as a data URL and opens the editor with a fixed `image` background (`Drawing` = `{ strokes, image? }`, world coordinates, image at 0,0). The canvas then gets a white background and no `mdlive-ink`; `toSvg` includes the image box in the crop, embeds it as `<image id="mdlive-background">` over a white `<rect>` (if all stroke points lie inside the image, the SVG is cropped exactly to the image: no padding, no `<rect>`) and stores its position in the metadata. Saved as `<timestamp>.image.drawing.svg` (`hasBackground`, not inverted in dark themes; `saveImage` keeps the double suffix); the node's `width` is reset. The editor resolves with the `Drawing`; `drawingFile` turns it into the file to save: the SVG, or, once all strokes are gone, the embedded image itself (from the data URL), in which case `editDrawing` restores the original `width` (`nodeWidth`, kept in the metadata). The global `keydown` listener ignores keys while the overlay is open. Touch pointers never draw (palm rejection); only the pointer that started a stroke continues it. With `mdLive.drawingDevice` = `ipad`, `ipadUsb` or `sidecar`, the webview loads the `Drawing` itself and sends it with `drawRemote`; `DrawingServer` (runs only on demand: `start()` on a drawing request or `mdLive.showIpadUrl`, stops `IDLE_MS` (2 min) after the last request, or when the setting leaves `ipad`; the iPad page keeps reconnecting via `connect()`; listens on all interfaces at `mdLive.ipadPort`, everything under `/<token>/`, token persisted in `globalState`; `mdLive.drawingDevice` = `ipadUsb` behaves like `ipad` but listens only on the USB cable's IPv4 address (`listenHost`/`usbAddresses`: interfaces with a 169.254.x.x IPv4 address and only link-local ones; excludes Wi-Fi, AirDrop's awdl0/llw0 and utun VPN tunnels, which also have fe80::; loopback without cable), so a Wi-Fi attempt via the `.local` name is refused and Safari falls back to the cable address; `addressCheck` rebinds every 3 s when the address changes (replugged) without dropping the pending request; the `asset` route only serves images the note links to inside its workspace folder, and results without a pending request are only saved into existing `.md` notes in the workspace (`noteUri`), since targets come from the client) pushes the request to the iPad page via server-sent events (`draw`/`cancel`, pending request resent on reconnect), the page POSTs `result` (`drawingFile` output) and the extension saves it via `saveImage`. Nothing drawn on the iPad page may get lost (`src/ipad/main.ts`, `localStorage`). Every request carries a `DrawingTarget` (note URI + image `src` from `drawRemote`, `null` for a new drawing). `openDrawingEditor`'s `onChange` keeps a draft per request id (ids are `Date.now()`, unique across extension restarts; no image data, only its box) that is restored when the same request arrives again (page reloaded, reconnect). Finished results go into an outbox (list) and are resent on every reconnect until the server answers; a `draw` for an id still in the outbox is ignored. The server saves a result whose request is gone (VS Code reloaded) itself via `saveToNote` (`liveEditor.ts`: saves into the target note's assets, replaces the old link in the text or appends the drawing at the end, saves the note if it was clean); `handled` ids are never saved twice. `stop()` (also on VS Code reload) sends no `cancel`, so the canvas stays open. A draft whose request was dropped or cancelled from the Mac becomes an orphan, offered on the next request (`confirm`): same target (or both new) → continue with its strokes; another drawing → edit the orphan instead (the current request is answered with `file: null`, the background image is fetched via the server's `asset` route, the result goes to the orphan's target). `sidecar` uses the same page in a browser window on the Mac (meant to sit full screen on the Sidecar display): the server then listens on `127.0.0.1` only, and `draw` calls `showOnSidecar`: a JXA snippet (`FIND_SIDECAR`, NSScreen name matching iPad/Sidecar) finds the display frame (if there is none, `connectSidecar` connects the iPad named in `mdLive.sidecarIpad` (name without macOS' ` (n)` suffix; empty = no auto-connect) via the private `SidecarCore` framework `SidecarDisplayManager`, waits on `connectedDevices`, then `FIND_SIDECAR` runs again in a fresh process because NSScreen doesn't refresh inside a running osascript); if it had to connect, the own Chrome instance is killed (its window would sit on the Mac display), otherwise an open window gets `RECONNECT_GRACE_MS` to (re)connect; then `openSidecarWindow` starts a separate Chrome instance (own `--user-data-dir` in `globalStorageUri`, so the flags apply while Chrome runs) opens it as `--app` window with `--window-position`/`--start-fullscreen` (no Chrome → `openExternal`); any `drawingDevice`/port change stops the server (restarted with the right interface on the next request). A cancellable progress notification on the Mac cancels the request.
- **Inline title:** Obsidian-style `<h1 id="title">` (`contenteditable`) above the editor in `getHtml`, not part of the Markdown. Shows the file name with `_` as spaces (`noteTitle`); on blur (`Enter` jumps to the start of the note, `Escape` reverts) the webview sends `rename`, `renameNote` (`liveEditor.ts`) saves the note and renames it via `WorkspaceEdit.renameFile` (`titleToFileName`: spaces → `_`, invalid characters → `-`; warns if the name is taken). VS Code then disposes the panel and opens a new one for the new file; `registerAssetSync` moves the assets folder. The global `keydown` listener ignores keys in the title. Once the title scrolls out of view (`IntersectionObserver`), a fixed compact copy `#titlebar` fades in at the top; clicking it scrolls up and focuses the title.
- **Moving blocks (`Alt+Up/Down`):** `src/webview/moveBlocks.ts`. In lists, `editListRows` flattens the outermost list into rows (item's own content + depth), applies a row edit and rebuilds the nested lists via `build` (depth clamped to previous depth + 1). `moveRows` moves only the selected rows by one row (sublists stay in place). Outside lists, blocks are swapped with their sibling. Registered as a `$prose` keymap before `crepe.create()`.
- **Tab in lists:** `indentListItems` (`moveBlocks.ts`) uses `editListRows` + `shiftRows` to change only the depth of the selected rows (sublists keep their depth; no-op on the first row or at depth 0) and always consumes `Tab`/`Shift+Tab` inside lists, so Crepe's `indent` plugin can't insert spaces. Called from the global capture `keydown` listener in `main.ts` (skipped inside CodeMirror code blocks); outside lists `Tab` keeps the default behavior.
- **Selection toolbar:** Crepe only re-evaluates its toolbar on selection/doc changes, so `style.css` hides `.milkdown-toolbar` while the editor has no focus (`:not(:focus-within)`).
- **Formatting shortcuts:** `Alt+B` bold, `Alt+I` italic, `Alt+S` strikethrough, `Alt+W`/`Alt+H` yellow highlight, `Alt+Q`/`Alt+E`/`Alt+R` red/green/blue highlight (`HIGHLIGHT_KEYS`), `Alt+C` inline code, `Alt+M` inline math. Mapped to Milkdown command names in `FORMAT_COMMANDS` (`main.ts`) and handled in the global `keydown` listener (with `Alt+K`), because clicking a formula focuses its tooltip, not ProseMirror. In lists, `listItemRange` expands the selection to the whole text of the touched items for all formatting commands except `ToggleLatex` (and `ToggleHighlight` with a non-empty selection) and for `Alt+K` (`runFormatCommand` restores the cursor afterwards).
- **Headings:** `Alt+1..6` set the heading level of the selected blocks (same level again → paragraph), `Alt+^` (key left of 1: `Backquote`/`IntlBackslash`, see `HEADING_KEYS` in `main.ts`) → paragraph, via `setHeading` (`headings.ts`). `Tab`/`Shift+Tab` in a heading shift its level by one (`shiftHeading`, called after `indentListItems` in the `Tab` branch of the `keydown` listener).
- **Collapsing sections (`Alt+Y`):** `src/webview/fold.ts`. `foldPlugin` keeps the positions of collapsed top-level headings and list items as view-only plugin state (mapped through transactions, not saved in the Markdown; persisted as `Fold` = level (0 = list item, text of its first paragraph) + text + occurrence `n` in `foo.assets/.folds.json` via the `folds` message whenever the list changes, loaded in `init` via `setFolds`, restored by text after `replaceAll` on `update`; `cleanupAssets` never trashes the file, `saveFolds` deletes it once nothing is collapsed) and hides the following top-level blocks up to the next heading of the same or a higher level via node decorations (`.mdlive-folded`, `display: none`). A collapsed list item hides its sublists and gets `.mdlive-collapsed-item` (ring around its bullet's SVG circle). Both get a `badge` widget at the end of the heading / first paragraph: a pill `.mdlive-fold-badge` with the number of hidden blocks / sub-items (VS Code badge colors) that expands on `mousedown`. `toggleFold` picks via `currentItem` a collapsed item the cursor is in, or in a sub-item the innermost item with a sublist (the sub-item itself or its parent); otherwise (also in top-level items) the heading whose section contains the cursor (`currentHeading`). The cursor moves to the end of the item's first paragraph or the heading; a section unfolds by itself when the cursor lands inside it. Matched via `e.key` (`¥` = Option+Y on Mac), so it works on QWERTZ and QWERTY.
- **Highlight:** `src/webview/highlight.ts` adds an Obsidian-style `==text==` mark with a `color` attr (remark plugin splitting text nodes + `<mark>` schema, `ToggleHighlight` command taking a color, input rule). Only `==…==` within a single text node is parsed. Yellow serializes as `==text==`, other colors as `<mark style="background: …;">` using the Obsidian Highlightr hex values in `HIGHLIGHT_COLORS`; `parseHtmlMarks` merges the separate inline `<mark …>`/`</mark>` html nodes back into colored highlights (unknown colors are kept as raw CSS). In the editor, `style.css` shows theme-neutral colors via `mark[data-color]`.
- **PDF notes:** `paper.pdf` keeps its notes in `paper.pdf.md` (`notesUri` in `assets.ts`, created on the first note; images in `paper.pdf.assets/` via the normal asset handling; renaming the PDF renames the notes file, which moves the folder; deleting the PDF in VS Code trashes the notes file and its folder). Format (`sidecar.ts`): `## Page N` = page section, its body is the page note; `### [label](#pN=x,y,w,h;…[&area][&c=color])` = text/area note, rectangles as fractions of the page (top left origin), label = selected text (`Area` for areas); headings inside fenced code are ignored, everything else is kept. Section key: `page:N` or the anchor string. The extension parses the file and sends `sections`; every card is a Crepe editor (`createNoteEditor`) of one body, created lazily when near the viewport (`cardObserver`). Edits replace only that section's body (`setNoteBody`, through `preserveSource`); the notes document is saved automatically (`SAVE_DELAY_MS`) since the read-only PDF tab never shows it dirty. Echo prevention: `ownText` skips `notes` for the webview's own edits, `echo` maps the stored body back to the webview's text when sections are resent, and cards compare against `card.source` and ignore bodies they sent recently (`card.sent`, late echoes that would reset a card while typing). Sizes: `fitScale` fits page + `notesWidth` (setting `mdLive.pdfNotesWidth`) at zoom 1 and multiplies by the user zoom (`Ctrl`+wheel); the notes column then fills the rest of the viewer (`sizePage`, at least `MIN_NOTES_WIDTH`) and gets CSS `zoom` = `notesZoom()` (the user zoom; when zooming in, at most the page scale but at least 1, so in narrow windows/split view, where pages start small, notes only grow once pages exceed their PDF size), so notes (the PDF's font size, images, toolbars) magnify together with the pages. Card tops and the column height are in the column's own (unzoomed) units; `drawLines` computes x positions (page at the row's left edge, column after `GAP`) instead of measuring the zoomed column, whose offsets/rects differ between Chromium versions (VS Code's Electron vs. current Chrome). Layout (`layoutRow`): cards of marks go onto the page itself (`.on-page`, one of `PAGE_CARD_WIDTHS` wide (narrower ones cost `NARROW_COST`, all heights measured in batches), without the quote (label) except for explanations, positioned from the margin with a negative `left`, `place` in PDF points) into the free spot closest to their mark (`placeOnPage`: summed-area table over a `CELL`-point grid, spots to the right weighted by `RIGHT_WEIGHT`, only if closer than the margin and within `MAX_PAGE_DISTANCE`, and only if the `connector` line crosses no content (`raw` grid) and no other card); free space comes from `inkGrid` (computed once per page from the first rendered canvas: cells differing from the most frequent color, grown by `INK_PAD`; busy backgrounds → everything occupied) plus all marks (`freeGrid`), placed cards reserve their cells and their connector's (`alongLine`), so nothing overlaps. A focused card or an expanded explanation keeps its spot (`pinned`; re-laid out once the focus has left the card). New notes (`openNote`'s `fresh`, or a card not laid out yet) and `Alt+P` in a card set `inMargin`: the card stays in the margin until the focus leaves it. Page notes and cards without room go into the margin, sorted by mark top (page note first), pushed below the previous card; the margin column (and thus the row) grows past the page; `drawLines` connects mark and card (on the page a straight line between the nearest points, to the margin a curve from the page edge) in an SVG per row. Zooming (`scheduleScale`): sizes and layout update once per frame (`applyScale`; text layers follow `--total-scale-factor`, old canvases are stretched), pages are re-rendered sharp `RENDER_DELAY_MS` after the gesture, sequentially, nearest first (`renderNearPages`); only rows in `nearPages` are laid out, others go to `staleRows` and are laid out when they come near, and far columns get `.far` (`content-visibility: hidden`; not on near ones, it would clip Crepe's menus); `layoutRow` reads all card heights before writing positions. Pages are rendered lazily (`pageObserver`, canvases released far away) with pdf.js' `TextLayer` (CSS copied into `pdf.css`); the worker is started from a blob (webviews can't load workers from resource URIs, hence `worker-src blob:`), `useWorkerFetch: false` makes the main thread fetch CMaps/fonts/wasm. Cards: every page always has a page note card (`emptyPageSection` when the file has none; placeholder via `createNoteEditor`'s `placeholder`); text/area notes only get a card when their body is non-empty or while being edited, so a mark with an empty body is a plain highlight (marks and the hit test `noteAt` use all sections, not the cards). Creating: text selection → `Alt+Q/W/E/R` (`HIGHLIGHT_KEYS` from `noteEditor.ts`) highlights only, with `Shift`, `Alt+A` (random color `h<hue>` via `randomColor`, away from red and green (`AVOID_HUES`) and the page's other random colors; CSS colors set inline by `setCustomColor`) or the popover's color dots also opens the note (`markSelection`; `selectionRects` merges the selected text nodes' rects per line; text marks the selection overlaps (`overlaps`) are replaced by the new mark, their bodies move over, via `addNote`'s `replace` keys); `Alt`+drag → area (random color like `Alt+A`; `snapshot` renders the region at `SNAPSHOT_SCALE` and saves it as image, inserted as the note's body as `![PDF area](…)`; `splitBody` hides a leading snapshot of an area note from its card (kept in the file for Claude, prepended again on `editNote`), so the card only edits the text after it). An empty text/area card is dropped when it loses focus (not while drawing), the mark stays, unless the note was just created with its card open (`freshNotes`, not when it replaced marks): then the mark is deleted too; `×`, `Shift+Delete`/`Shift+Backspace` inside a card (a page note is emptied instead) or `Delete`/`Backspace` while the pointer is over a mark (`hoveredMark`, not while a card or other editable has focus) deletes mark and note (`removeNote`); clicking a mark opens its card (`openNote`). `Shift+Enter` in a card (outside code blocks) finishes editing it (blur); when a card loses focus, `removeEmptyItems` drops bullets without text (a list left empty goes as a whole). Formatting shortcuts act only on a focused card (`setActiveEditor(undefined)` on clicks in the document). `Cmd+Z`/`Cmd+Shift+Z` outside the cards (inside, ProseMirror's own undo) sends `undo`: the extension keeps `undoStack`/`redoStack` of `Step`s (notes added + removed by one `addNote`/`deleteNote`; undoing removes the added ones with their current body and re-adds the removed ones); `discard` (auto-removed fresh mark) pops its own add step instead. `Alt+Y` folds in the focused card (found from `document.activeElement`, the key is always consumed inside cards) via `foldPlugin`; folds are kept per section key in `paper.pdf.assets/.folds.json` (`folds` in `init`, webview → ext `folds` with the whole record, `saveCardFolds` drops keys of deleted notes).
- **Explanations by Claude:** the user-level skill `explain-slides` (`~/.claude/skills/explain-slides/SKILL.md`, not in this repo) writes `paper.pdf.claude.md` (`explanationsUri`; renamed/trashed with the PDF in `registerAssetSync`): one `## Page N` section per slide, body = bold key message (first paragraph) + bullets in German, unknown terms as `- **Term:** …` bullets. Older files may still have `### [term](#pN)` sections (`NOTE_HEADING`/`parseAnchor` accept anchors without `=`; `parseExplanations` keys them `pN|term`); `pageExplanation` (`sidecar.ts`) merges them into the page's text as bullets. The extension watches the file (`createFileSystemWatcher`, Claude writes it on disk) and sends it as `explanations`; the webview shows each page's explanation as a read-only zone `.claude` at the top of the page note card (`Card.claude`, `createClaude`/`updateClaude`; `.has-claude` on the card): the key message always (`claude-summary`, after a sparkle drawn as CSS mask in the soft violet `--explain`; a `claude-chevron` rotates when open), the rest when open (`.open`: `expandExplanations` from the setting `mdLive.pdfExplanationsExpanded`, flipped per page by a plain click on the head (`toggled`; dragging selects the text instead); read-only Crepe editor via `ensureClaudeEditor`, created only once the card's own editor exists, i.e. near the viewport). So authorship stays visible: Claude's text lives only in `.claude.md` and is always read-only (deliberately no way to move it into the own notes), the user's own text below it in the page note. `×` (`deleteExplanation`, `page`) dismisses it via `clearExplanation` (keeps an empty `## Page N`, so the page still counts as explained), undoable with `Cmd+Z` like notes: the `Step` then carries the explanations file before/after (restored only if Claude didn't write it meanwhile); `×` blurs the focused card so `Cmd+Z` reaches the global undo. The `notes` message after undo carries `reset` (changed keys): those cards take the new body even if it is in `card.sent` (undo often restores a body the card sent itself). The lightbulb in the PDF editor title (`mdLive.toggleExplanations` / `.off`, picked via `config.mdLive.pdfExplanationsExpanded`) expands/collapses all; `mdLive.pdfExplanations` (settings only) hides them. Generating: `mdLive.explainSlides` (sparkle in the PDF editor title; `.running` with a spinner while the context key `mdLive.explaining` is set for the active PDF, `PdfEditorProvider.active`/`updateContext`) opens a quick pick in `explain.ts`: the next `CHUNK` (10) unexplained pages from the page in view (`PdfView.page`, from the webview's `view` message), a page range, slides about a topic (the prompt carries every page's text, `PAGE_TEXT_LENGTH` chars from `requestPageTexts`, so Claude reads only the matching pages) or all unexplained ones (page modes also send an outline, `OUTLINE_LENGTH` chars of every page, so Claude skips terms later slides cover); a page counts as explained once the file has any section for it. It then runs `claude -p` in the PDF's folder in the background (prompt on stdin, `--allowedTools Read,Skill,Edit(//<file>)`: Claude can only write the explanations file; PATH extended for VS Code started from the Dock), one run per PDF, with a cancellable progress notification; the watcher shows the results live. `claudeContext` includes the page's explanations. `Alt+K` with text selected in an explanation (`explanationSelection`) or the pointer over one (`hoveredClaude`) sends `askClaude` with `explanation: true` (and the selection as `quote`); the context then names that passage/explanation instead of a marked passage.
- **Claude hand-off (`Alt+K`):** the Claude Code extension only reads selections from real text editors. So: save the document (avoids a save prompt when closing the temp tab; Claude reads from disk), map the plain-text selection heuristically to source lines via `findSourceRange`/`stripMarkdown`, briefly open the file as a text editor, select the lines, run `claude-vscode.insertAtMention`, then close the temporary tab and reopen the tab that was active in the group (`vscode.openWith` with its `TabInputCustom`; `panel.reveal` alone left another file active). In the PDF view, `Alt+K` inside a card with selected text does the same with `paper.pdf.md`; without a selection, or with the pointer over a note card (`hoveredCard`), it sends `askClaude` with the card's `key` and `note: true` (the context then quotes that note under "My note in question"); outside the cards (`askClaude` in `webview/pdf/main.ts`) it sends the PDF selection, else the mark under the pointer (`hoveredMark`), else the page taking up most of the window (`pageInView`); `claudeContext` (`pdfEditor.ts`) writes `paper.pdf.assets/.claude.md` (`writeClaudeContext`, kept by `cleanupAssets` like `.folds.json`) with the page, quote/mark with its position (anchor string, tells apart repeated passages), the raw sections of that page in a code fence (`fenced`) and the instruction to read only that page of the PDF (Read tool's `pages`), and mentions the whole file via `sendSelectionToClaude`.

## Conventions

- TypeScript strict, 2 spaces, single quotes, trailing commas; short English comments only for non-obvious logic.
- Minimal error handling: report problems via `vscode.window.showWarningMessage` rather than catching errors.
- `dist/`, `node_modules/` and `*.vsix` are generated; do not edit by hand.
- `notes/` only contains test notes for the development instance.
